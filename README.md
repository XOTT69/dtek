# 💡 Світло Київщини — усі 12 підгруп (1.1–6.2)

Безплатний open-source бот для автоматичної публікації графіків електропостачання **Київської області** (не м. Київ) у Telegram-каналі або групі.

## Автоматичні оголошення «Укренерго»

Крім 12 підгруп ДТЕК бот **автоматично перевіряє офіційний публічний Telegram-канал [@Ukrenergo](https://t.me/Ukrenergo)** та шукає оголошення про **погодинні відключення на завтра**. Для отримання даних не потрібен сторонній Telegram-бот чи новий токен.

- Публікує **лише свіже повідомлення** офіційного каналу з підтвердженими датою й інтервалом дії обмежень. Визначає інтервали **погодинних відключень населення**, не плутаючи їх із графіками обмеження потужності для бізнесу.
- Розрізняє «в усіх регіонах», явну згадку Київської області та «у частині регіонів». В останньому випадку **не стверджує**, що відключення вже запроваджені на Київщині.
- Публікує одне повідомлення на день, якщо є нові перевірені відомості, та **редагує його**, коли «Укренерго» змінює оголошені години. Повторів немає.
- Додає посилання на конкретний допис офіційного каналу; **графіки окремих підгруп залишаються за ДТЕК**.
- Зберігає публікації в `state/publications.json` у секції `announcements`. Можна вимкнути через GitHub Actions Variable `UKRENERGO_NOTICES=off`.
- Якщо Telegram не повертає публічні дописи, **основний бот ДТЕК продовжує працювати**. Інформація з інших неофіційних каналів не використовується.

Приклад для оголошення лише про частину регіонів:

```text
⚡️ Завтра, 17.10, можливі погодинні відключення
🕒 06:00–23:59

📍 У частині регіонів України.
💡 Точні години підгруп 1.1–6.2 повідомимо після публікації графіка ДТЕК.
📢 Офіційне повідомлення Укренерго
```

## Що він уміє

- Стежить за всіма **12 підгрупами: 1.1, 1.2, 2.1, 2.2, 3.1, 3.2, 4.1, 4.2, 5.1, 5.2, 6.1, 6.2**.
- Публікує графіки **на сьогодні** і **на завтра** тільки за наявності підтверджених денних даних `fact` для всіх 12 підгруп. Якщо ДТЕК ще не дав графік на завтра — бот нічого про завтра не надсилає. Усі 12 підгруп зазвичай публікуються одним повідомленням; лише коли текст надто довгий для Telegram, бот автоматично розділяє його.
- Точно перетворює 24 годинні значення на **30-хвилинні інтервали** та об'єднує сусідні проміжки.
- Показує час кожного відключення та сумарну тривалість для кожної підгрупи.
- Використовує лише **підтверджений денний графік** `fact` (❌); **не публікує тижневі `preset`/«можливі» відключення** та довгі прогнозні пости.
- Публікує нові повідомлення **тільки за зміни графіка або дати**, не реагуючи на оновлення службового timestamp.
- При зміні підтвердженого графіка надсилає одне оновлене повідомлення з усіма групами. Під час переходу зі старого формату бот редагує першу з двох частин через `editMessageText` і видаляє зайву другу без нових повідомлень.
- Приблизно **за 30 хвилин до HH:00 / HH:30** нагадує про майбутній початок та завершення відключень і підгрупи, що залишатимуться без світла. Через затримку GitHub Actions фактичний час випередження може бути **10–30 хвилин**, бот показує, скільки часу залишилося. Після початку слота запізнілі нагадування не публікуються. Використовуються тільки підтверджені `fact`, включно з переходом через північ.
- Зберігає хеші повідомлень та ключі часових сповіщень у `state/publications.json`. Вже відправлений часовий слот повторно не публікується.
- Не потребує власного сервера: GitHub Actions налаштовано на перевірку **кожні 5 хвилин**. Планувальник GitHub працює за принципом best effort — інколи запуски затримуються або пропускаються.

**Основне джерело — безпосередньо офіційний сайт ДТЕК Київські регіональні електромережі**: [dtek-krem.com.ua/ua/shutdowns](https://www.dtek-krem.com.ua/ua/shutdowns). Скрипт спочатку пробує AJAX сайту, а якщо він недоступний — публічний HTML із даними `DisconSchedule.fact`. Для такого підключення не потрібні платні сервіси, браузер Playwright або сторонній парсер. Це інтеграція з вебсторінкою ДТЕК, **не офіційний документований API**.

Якщо сайт ДТЕК захищає запити, змінює структуру або тимчасово недоступний, бот використовує **резервний** JSON [Baskerville42/outage-data-ua](https://github.com/Baskerville42/outage-data-ua). Обидва джерела проходять перевірку даних перед публікацією; тижневий прогноз `preset` не розсилається.

## Архітектура

```text
ДТЕК (офіційний сайт) ─────────────┐
     │                             │
     │  прямий HTML / AJAX         │ якщо недоступний
     ↓                             ↓
  Дані fact                  outage-data-ua (резерв)
     └──────────────┬──────────────┘
                    ↓
           GitHub Actions (~5 хв)
                    ↓
          Перевірка даних і дат
                              ↓
                GPV1.1–GPV6.2 / тільки денний факт
                              ↓
                 Порівняння з минулою публікацією
                              ↓
                       Telegram Bot API
                              ↓
                      Telegram-канал/група
```

### Налаштування Telegram (одноразово)

1. У [@BotFather](https://t.me/BotFather) надішліть `/newbot`, задайте ім'я та username; скопіюйте **токен**. **Не публікуйте його в репозиторії**.
2. Створіть **Telegram-канал** (для автоматичних оголошень він простіший за групу). Якщо канал публічний, призначте йому username, наприклад `@your_light_channel`.
3. Додайте нового бота **адміністратором каналу** з правом **публікувати повідомлення**. Для приватного каналу потрібен цифровий `chat_id` (починається з `-100`); для публічного підійде `@channel_username`.
4. У цьому репозиторії відкрийте **Settings → Secrets and variables → Actions → New repository secret** і створіть:
   - `TELEGRAM_BOT_TOKEN` — секретний токен BotFather;
   - `TELEGRAM_CHAT_ID` — `@channel_username` або цифровий ID каналу/групи.
   - **Необов'язково:** у **Settings → Secrets and variables → Actions → Variables** задайте `TELEGRAM_CHANNEL_USERNAME`, якщо хочете додавати посилання на канал у короткі сповіщення та використовуєте цифровий chat ID. Значення: `@username_каналу`.
5. У **Settings → Actions → General** переконайтеся, що Actions дозволено запускатися, а workflow має право запису до репозиторію (`contents: write`), щоб зберігати стан публікацій.
6. Відкрийте вкладку **Actions → DTEK schedules to Telegram → Run workflow**. Після успішного запуску нові повідомлення з'являться в каналі; надалі перевірка працює автоматично.

Ті самі два секрети підходять і для Telegram-групи, якщо бот має право надсилати повідомлення.

### Джерело графіків

За замовчуванням: `SOURCE_MODE=auto` — паралельно перевіряються **офіційний сайт ДТЕК і резервний JSON**. Порівнюємо час зміни саме графіків `fact.update`, а не час HTTP-запиту; використовуємо найновіший підтверджений графік. Якщо часи збігаються, пріоритет за прямим ДТЕК. Це допомагає не пропускати оновлення через затримки кешування сайту.
У GitHub Actions можна додати Variables `SOURCE_MODE=fallback`, щоб тимчасово використовувати тільки старий JSON, або `SOURCE_MODE=direct`, щоб тестувати лише пряме джерело. Змінювати секрети Telegram не потрібно.

У логах публікації видно `DIRECT DTEK (html)` / `DIRECT DTEK (ajax)`, або `BACKUP outage-data-ua`. Пряме джерело не перевіряється через посередницький репозиторій.

### Перевірка формату

Потрібен Node.js 20+ (у GitHub Actions використовується Node.js 22).

```bash
npm test
DRY_RUN=1 npm start
```

`DRY_RUN` виводить повідомлення у консоль, **нічого не надсилає** й не записує стан. Для звичайного запуску потрібні змінні оточення `TELEGRAM_BOT_TOKEN` та `TELEGRAM_CHAT_ID`.

## Фрагмент підтвердженого графіка

Формат **сумісний із парсером XOTT69/botvoda**: заголовок групи містить «відключення:»,
часи на рядках з `❌з ... до ...`, тривалість у годинах із **крапкою** та однією цифрою.

```text
💡Оновлений графік відключення світла на сьогодні.
📆П'ятниця, 16.10.2026

💡Підгрупа 1.2 відключення:
❌з 09:30 до 11:30 (2.0 год)
❌з 18:00 до 22:00 (4.0 год)
⚫ Разом без світла: 6.0 год

💡Підгрупа 2.2 відключення:
❌з 09:00 до 15:00 (6.0 год)
❌з 18:00 до 22:00 (4.0 год)
⚫ Разом без світла: 10.0 год
```

Це фрагмент двох підгруп (дата 16.10.2026, підтверджене оновлення об 11:20).
У фактичному повідомленні зазвичай присутні всі 12 підгруп. Періоди
формуються з поточних даних ДТЕК, а не із прикладу. Переслане в Telegram
повідомлення може бути прочитане ботом для води без переформатування.


Якщо `fact` для завтра відсутній, **бот не публікує жодного повідомлення на завтра**. Коли з'являється денний `fact` для всіх підгруп, відправляється підтверджений графік. Тижневі прогнози `preset` ніколи не публікуються.

## Сповіщення про півгодинні зміни

Коли за підтвердженим денним графіком настає півгодинний слот зі змінами, бот формує, наприклад:

~~~text
⏰ 09:30
🔔 До планового часу: 30 хв

🔴 Початок відключення:
🪫 Підгрупа 1.1
🪫 Підгрупа 1.2
🪫 Підгрупа 2.1

🌑 За графіком залишаються без світла:
⚫️ Підгрупа 2.2
⚫️ Підгрупа 5.1
⚫️ Підгрупа 5.2
⚫️ Підгрупа 6.1
~~~

При завершенні планового відключення окремий блок містить
**🟢 Завершення планового відключення** та позначення **🔋 Підгрупа ...**.
Фразу про підтвердження фактичного стану мережі більше не додаємо.


Список взято з тестового знімка `kyiv-region.json` від 16.10.2026; фактичні публікації формуються з найновішої доступної версії.

Якщо жоден статус у цей слот не змінюється, повідомлення **не надсилається**. Бот також показує підгрупи, для яких за розкладом **закінчилося** відключення. Часткові години (`first`, `second`) враховано коректно.

Рекомендована назва каналу — **💡 Світло Київщини | Графіки відключень**, запропонований username — `@svitlo_kyivshchyna` (доступність перевіряється в Telegram).

### Публікації без зайвого тексту

У Telegram показуємо тільки дату, підгрупи, проміжки відключення та сумарну кількість годин.
**Прибрано:** рядки про час оновлення ДТЕК, дисклеймер про фактичну наявність світла та посилання на першоджерело.
Оригінальне джерело й авторство залишаються в цьому README.

Уже надіслані **підтверджені** графіки можуть бути відредаговані ботом без нових повідомлень. Раніше розіслані **прогнозні** пости автоматично не видаляються: їх можна прибрати з каналу вручну.

## Надійність та межі

- Дані джерела: [data/kyiv-region.json](https://github.com/Baskerville42/outage-data-ua/blob/main/data/kyiv-region.json); часовий пояс — `Europe/Kyiv`.
- Коли ДТЕК тимчасово не дозволяє парсинг, `outage-data-ua` залишає останні успішні `fact` і `preset`. Бот може **використати цей знімок**, якщо з моменту `lastUpdated` минуло **не більше 12 годин**, і виводить попередження у логах.
- Якщо дані старші за 12 годин, структура JSON зламана або немає збережених графіків, публікація зупиняється з поясненням; прострочений графік не видається за актуальний. Збої мережі при завантаженні JSON перевіряються повторно (до 3 спроб).
- Нові публікації створюються тільки для дат з підтвердженим розкладом. При зміні хоча б одного інтервалу надсилається оновлення відповідної частини. Для півгодинних сповіщень є захист від повторного надсилання.
- GitHub Actions **не гарантує точні 5-хвилинні запуски**: можливі затримки/пропуски, а також затримки оновлення офіційних даних. Нагадування відправляються **до перемикання**, коли залишається 10–30 хвилин; після початку старі слоти не «доганяються». Для гарантовано точного випередження рівно на 30 хвилин потрібен постійний планувальник.
- Планові завершення відключення не гарантують, що електропостачання вже фактично відновилося.
- Бот **не визначає реальну наявність світла** в конкретному будинку — лише публікує графік постачальника.
- Репозиторій не пов'язаний офіційно з ДТЕК.
